# Environment Variables

Defaults below are the values baked into the code (`backend/app/...`). The backend reads every variable through `app/knobs.py` ([conventions §1–§2](conventions.md#1-configuration-is-read-only-through-appknobs)), and `tests/unit/test_house_rules.py` fails if a variable it reads is missing from the Backend table, or is documented there with a different literal default. Copy `backend/.env.example` and `frontend/.env.example` as starting points.

## Backend

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | — (**required**) | SQLAlchemy database URL. The app raises at startup if unset or unreachable (`models/database.py`). |
| `DEPLOYMENT_MODE` | `standalone` | `standalone` (backend validates tokens) or `gateway` (Tyk terminates auth at the edge). Selects the middleware stack (`middleware/factory.py`). |
| `DESCOPE_PROJECT_ID` | `""` | Descope project ID; required for token validation and management calls. The app refuses to start when it is unset (`main.py` lifespan). |
| `DESCOPE_MANAGEMENT_KEY` | `""` | Descope management key; required for provider sync and management operations. The app refuses to start when it is unset (`main.py` lifespan). |
| `DESCOPE_BASE_URL` | `https://api.descope.com` | Descope API base URL (override for custom domains/testing). |
| `DESCOPE_WEBHOOK_SECRET` | `""` | Shared secret guarding `POST /api/internal/webhooks/descope`. Unset ⇒ the endpoint rejects all requests. |
| `DESCOPE_FLOW_SYNC_SECRET` | `""` | Shared secret guarding `POST /api/internal/users/sync`. Unset ⇒ the endpoint rejects all requests. |
| `INTERNAL_IDENTITY_KEY` | `""` | Shared secret guarding `GET /api/internal/identity`. Unset ⇒ the endpoint rejects all requests. |
| `IDENTITY_CACHE_TTL` | `300` | Identity-resolution cache TTL, seconds (`services/identity_resolution.py`). |
| `RATE_LIMIT_DEFAULT` | `60/minute` | Default per-route rate limit. |
| `RATE_LIMIT_AUTH` | `10/minute` | Rate limit for auth-sensitive routes. |
| `TRUSTED_PROXY_HOSTS` | `127.0.0.1` | Comma-separated proxy hosts trusted for forwarded headers. |
| `FRONTEND_URL` | `http://localhost:3000` | CORS allowed origin. |
| `REDIS_URL` | — | Redis URL (`redis://` or `rediss://`) for cross-instance cache invalidation. Unset, another scheme or unreachable ⇒ cache invalidation disabled (single-instance only). |
| `LOG_LEVEL` | `INFO` | Log level. |
| `ENVIRONMENT` | `development` | `production` turns on HSTS and the strict default CSP, and switches logs to JSON (`middleware/security.py`, `logging_config.py`). |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `""` | OTLP endpoint; empty disables telemetry export. |
| `OTEL_SERVICE_NAME` | `identity-stack` | OpenTelemetry service name. |
| `CSP_POLICY` | `default-src 'self'` in production; a localhost-friendly policy otherwise | `Content-Security-Policy` header value (`middleware/security.py`). |
| `ORY_ISSUER_URL` | `""` | Ory issuer URL. Set ⇒ Ory is added as a configured token provider alongside Descope (`middleware/providers.py`). |
| `ORY_AUDIENCE` | — | Ory access-token audience to enforce. Required when `ORY_ISSUER_URL` is set and audience validation is on. |
| `ORY_REQUIRE_AUDIENCE` | `true` | Ory audience validation switch. Only `false`, `0` or `no` turn it off; any other value leaves it on (`knob_flag`). |
| `ORY_CLIENT_ID` | — | OAuth2 client id sent on Ory RP-initiated logout. Unset or empty ⇒ `ORY_AUDIENCE`. |
| `ORY_POST_LOGOUT_REDIRECT_URI` | — | Where Ory sends the browser after logout. Unset or empty ⇒ `FRONTEND_URL` + `/login`. Must be registered on the Ory client. |
| `KEYCLOAK_ISSUER_URL` | `""` | Keycloak realm issuer, `<KC_HOSTNAME>/realms/<realm>`, exactly as in the token's `iss`. Set ⇒ Keycloak is added as a configured token provider (`middleware/providers.py`). Authorization is canonical: list `keycloak` in `CANONICAL_RBAC_PROVIDERS`, or a Keycloak principal is granted nothing. |
| `KEYCLOAK_AUDIENCE` | `""` | Client id of the realm's API client (case-sensitive), which the SPA's access tokens carry in `aud`. A token whose `aud` does not contain it gets 401. Required when `KEYCLOAK_ISSUER_URL` is set: the backend refuses to start without it. With `SYNC_PROVIDER=keycloak` the admin adapter keeps the canonical permissions and roles as this client's roles. Output `api_audience` of `infra/keycloak`. |
| `KEYCLOAK_CLIENT_ID` | `""` | Client id of the SPA's public client (case-sensitive): the `azp` an access token must carry. A token of any other client gets 401, and so does any token whose `typ` is not `Bearer` (the SPA's ID and refresh tokens). Also the client id sent on RP-initiated logout. Required when `KEYCLOAK_ISSUER_URL` is set: the backend refuses to start without it. Output `spa_client_id` of `infra/keycloak`. |
| `KEYCLOAK_REQUIRE_HTTPS` | `true` | Require HTTPS for Keycloak discovery and JWKS, in token validation and in logout. Only `false`, `0` or `no` turn it off; any other value leaves it on (`knob_flag`). It may be off only for a local issuer: the backend refuses to start with it off unless the issuer host is `localhost`, a loopback address or a name ending in `.localhost`. The exemption is by the name as it is written, not by what the name resolves to: a `.localhost` name that DNS or a hosts file points at another machine is still trusted, so turn this off for local development and tests only. The backend logs a warning at startup whenever it is off. Plain HTTP on `localhost` or a loopback address is allowed either way. |
| `SYNC_PROVIDER` | `descope` | The provider the canonical services push tenants, users and role assignments to: `descope` (`DescopeSyncAdapter`), `keycloak` (`KeycloakSyncAdapter`, [docs/keycloak.md](keycloak.md#admin-adapter); it pushes tenants, users, memberships, permissions, roles and role assignments) or `zitadel` (`ZitadelSyncAdapter`, [docs/zitadel.md](zitadel.md#admin-adapter); it pushes tenants and users, not role assignments, which stay canonical). Read once at startup; any other value stops startup. With `keycloak`, a role assignment adds the target to the tenant's Keycloak organization, so a role is assigned only to a user who already holds one in the tenant (anyone else is refused, 403; the first membership comes from signing in, [identity-stack#592](https://github.com/jamescrowley321/identity-stack/issues/592)). |
| `RELATIONSHIP_STORE` | `""` | The relationship store the FGA and document routes use (`app/services/relationship_store.py`): `descope` (Descope's FGA store, `DescopeRelationshipStore`), `openfga` (`OpenFgaRelationshipStore`, `app/services/openfga.py`) or `none` (no store: the FGA and document routes answer 404). Unset ⇒ the sync provider's: Descope's store when `SYNC_PROVIDER` is `descope`, OpenFGA when it is `keycloak` or `zitadel`, which have no Zanzibar-style store of their own. An Ory deployment syncs to no provider of its own, so it sets `openfga` itself. Read once at startup; any other value stops startup with `RelationshipStoreNotAvailable`. Each store serves only the principals whose ids it keys on: Descope's store a Descope principal, OpenFGA a principal of a provider in `CANONICAL_RBAC_PROVIDERS` (by canonical tenant and user id, never the token's `sub`). Everyone else gets 404 on those routes. Existing Descope FGA tuples are not copied to OpenFGA. |
| `OPENFGA_API_URL` | — | Base URL of the OpenFGA HTTP API, e.g. `http://localhost:8380` (compose `openfga` profile, from the host), `http://openfga:8080` (the same server, from a backend container in the compose network) or `http://localhost:18380` (`make test-up-openfga`). Required when the relationship store is `openfga`: startup reads the configured authorization model once and stops when a setting is missing, OpenFGA does not answer, or it holds no such store or model. Output `backend_environment` of `infra/openfga`. |
| `OPENFGA_STORE_ID` | — | The OpenFGA store the backend reads and writes relations in. Required with `openfga`. Output `backend_environment` of `infra/openfga`. |
| `OPENFGA_AUTHORIZATION_MODEL_ID` | — | The authorization model every check and write names. Required with `openfga`. `infra/openfga` writes the model (`infra/openfga/model.json`); the backend never does, so `PUT /api/fga/schema` answers 409 on OpenFGA. A new model is a new id: apply the root and restart the backend with its output. |
| `OPENFGA_API_TOKEN` | — | Pre-shared key sent as `Authorization: Bearer` to an OpenFGA server that requires one. Unset: no `Authorization` header (the compose servers run without authentication on loopback). Never logged. |
| `KEYCLOAK_ADMIN_CLIENT_ID` | — | Client id of the service account the Keycloak admin adapter writes with. Required when `SYNC_PROVIDER=keycloak`, with `KEYCLOAK_ISSUER_URL` naming the realm and `KEYCLOAK_AUDIENCE` the API client: startup takes a token, makes one Admin API read with it, reads its service account's `realm-management` roles and looks the API client up, and stops when a setting is missing, Keycloak refuses the credential, the service account lacks `manage-users`, `manage-organizations`, `query-clients` or `view-events`, or it cannot find the API client or manage its roles. The client holds those four roles, the fine-grained admin permissions `view`, `manage` and `map-roles-composite` on the API client alone, and the `kc-admin-api` client scope ([keycloak/fixtures/README.md](../keycloak/fixtures/README.md#the-admin-service-account)). It can write every user, organization and API client role, so its secret is as sensitive as a realm admin's. Example: `identity-stack-admin`. |
| `KEYCLOAK_ADMIN_CLIENT_SECRET` | — | That client's secret. Required when `SYNC_PROVIDER=keycloak`. Never logged; the startup refusal names the variable, not the value. The compose realm's value is a local fixture. |
| `KEYCLOAK_REGISTRATION_TOKEN_KEYS` | — | Comma-separated Fernet keys (`python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`) that seal the registration token of each Keycloak machine client in `machine_credentials` ([#698](https://github.com/jamescrowley321/identity-stack/issues/698)). Keycloak answers that token with the client's secret, so it is never stored in plain text. Required when `SYNC_PROVIDER=keycloak`: startup stops when it is unset or holds a value that is not a Fernet key. The first key seals; every listed key opens, so rotate by putting a new key first and keep the old one listed while any credential sealed under it remains. A lost key leaves those credentials' clients deletable only by a realm admin: deleting such a credential through `/api/keys` deactivates it, disables its client's service account and answers 502 (its tokens are refused from then on); once a realm admin has removed the client, so Keycloak answers `Could not find client`, the next delete removes the credential. A token stored unsealed (written before `011_seal_registration_tokens`, or by a 010 instance afterwards) is never read as plain text: its delete answers 502 and changes nothing until the migration seals it (stamp back to `010_machine_credentials` and upgrade again if 011 is already applied; the upgrade leaves sealed tokens as they are). `alembic upgrade` past `011_seal_registration_tokens` needs it when tokens are already stored, and seals them; a token that already opens under a listed key is left as it is. Never logged; errors name the variable, not the value. |
| `KEYCLOAK_PULL_EVENTS` | `true` | With `SYNC_PROVIDER=keycloak`, pull the realm's admin and user events into the canonical model ([docs/keycloak.md](keycloak.md#event-pull)): a user disabled, edited or deleted, an organization edited, disabled or deleted, a member or role group membership added or removed, an API client role created, edited or deleted in Keycloak reaches Postgres within one poll. Only `false`, `0` or `no` turn it off (`knob_flag`); off, nothing done in Keycloak reaches the backend, so a user disabled there keeps their canonical grants. Read once at startup. |
| `KEYCLOAK_PULL_INTERVAL_SECONDS` | `10` | Seconds between two polls of the Keycloak event pull. Read once at startup when `SYNC_PROVIDER` is `keycloak`; a value that is not a positive, finite number stops startup. A change made in Keycloak takes up to this long, plus the poll itself, to be refused or granted by the backend. |
| `KEYCLOAK_PULL_PAGE_SIZE` | `100` | Events the Keycloak event pull reads per Admin API page and applies per database transaction. Read once at startup when `SYNC_PROVIDER` is `keycloak`; a whole number from 1 to 1000, anything else stops startup. |
| `KEYCLOAK_POST_LOGOUT_REDIRECT_URI` | — | Where Keycloak sends the browser after logout. Unset or empty ⇒ `FRONTEND_URL` + `/login`. Must be registered on the SPA client. The logout client id is `KEYCLOAK_CLIENT_ID`. |
| `ZITADEL_ISSUER_URL` | `""` | Zitadel instance issuer, exactly as in the token's `iss` (local: `http://zitadel.localhost:8480`). Set ⇒ Zitadel is added as a configured token provider (`middleware/providers.py`). Authorization is canonical: list `zitadel` in `CANONICAL_RBAC_PROVIDERS`, or a Zitadel principal is granted nothing. |
| `ZITADEL_AUDIENCE` | `""` | The project id. A token whose `aud` does not contain it gets 401. Required when `ZITADEL_ISSUER_URL` is set: the backend refuses to start without it. |
| `ZITADEL_CLIENT_ID` | `""` | Client id of the SPA application (case-sensitive). A token whose `client_id` is anything else (another application in the project, a machine user) gets 401, and so does any token carrying `azp`, `at_hash`, `auth_time`, `sid` or `nonce` (an ID token). Also the client id sent on RP-initiated logout. Required when `ZITADEL_ISSUER_URL` is set: the backend refuses to start without it. |
| `ZITADEL_REQUIRE_HTTPS` | `true` | Require HTTPS for Zitadel: discovery and JWKS in token validation, the logout discovery fetch and the first-login UserInfo fetch. Only `false`, `0` or `no` turn it off; any other value leaves it on (`knob_flag`). While it is on, the backend refuses to start with an `http` issuer, loopback included. The local instance needs `false`; the backend logs a warning at startup whenever it is off. |
| `ZITADEL_POST_LOGOUT_REDIRECT_URI` | — | Where Zitadel sends the browser after logout. Unset or empty ⇒ `FRONTEND_URL` + `/login`. Must be registered on the SPA application. |
| `ZITADEL_ADMIN_TOKEN` | `""` | Personal access token of the machine user the Zitadel sync adapter calls the instance as, with the instance role `IAM_ORG_MANAGER` (in the `backend_environment` output of `infra/zitadel`, which `make zitadel-env` prints). Required when `SYNC_PROVIDER` is `zitadel`, with `ZITADEL_ISSUER_URL` (the instance) and `ZITADEL_AUDIENCE` (the project granted to each new organization): the backend refuses to start without them. Never logged; the refusal names the variable, not the value. |
| `ZITADEL_ADMIN_TIMEOUT_SECONDS` | `10` | Timeout, in seconds, of each call the Zitadel sync adapter makes. Read once at startup when `SYNC_PROVIDER` is `zitadel`; a value that is not a positive, finite number stops startup. |
| `JIT_ENABLED_PROVIDERS` | `ory` | Comma-separated providers whose first-login users are provisioned just in time by `GET /api/identity`. A provider is provisioned for only when its row exists in the canonical `providers` table (`scripts/seed_ory.py`, `scripts/seed_keycloak.py`). Keycloak is opt-in (`ory,keycloak`, row and tenant links from `make keycloak-seed`): a first-login user joins, as `member`, the one active tenant whose `external_org_id` is the one alias in the token's `organization` claim and whose `external_org_provider_id` is the `keycloak` row, with `email`, `email_verified` and the names from the access token, under the same email rules as Zitadel's below; a token with no `organization` claim, two aliases, an alias no tenant is linked to, or an email that is missing, unverified or outside the tenant's domains provisions nothing. Zitadel is opt-in too (`ory,zitadel`, row from `scripts/seed_zitadel.py`): a first-login user joins, as `member`, the one active tenant whose `external_org_id` is the token's organization (`urn:zitadel:iam:user:resourceowner:id`) and whose `external_org_provider_id` is the `zitadel` row, with `email`, `email_verified` and the names from UserInfo, for an email whose domain is one of that tenant's `domains`; a token with no organization, an organization no tenant is linked to, an email outside the tenant's domains, an email that is missing or unverified, or a UserInfo `sub` that differs from the token's provisions nothing. |
| `CANONICAL_RBAC_PROVIDERS` | `ory` | Comma-separated providers whose tenant, roles and permissions come from the canonical model rather than token claims. A caller in several tenants selects one with the `X-Tenant-ID` request header ([conventions §18](conventions.md#18-one-resolver-decides-the-tenant-and-the-grants)). Descope is excluded by default and **must not be listed**: its routes hand the tenant from its own token claims to Descope, so startup fails with `ProviderConfigurationError` when a provider that is Descope-managed is in this list. A Zitadel deployment lists `zitadel` and a Keycloak deployment `keycloak` (`ory,zitadel,keycloak`): neither has a claims extractor, so unlisted it is granted nothing. |

> **Never set any `OTEL_INSTRUMENTATION_HTTP_CAPTURE_HEADERS_*` variable** (`_CLIENT_REQUEST`, `_CLIENT_RESPONSE`, `_SERVER_REQUEST`, `_SERVER_RESPONSE`). The OpenTelemetry httpx and FastAPI instrumentors read them themselves and would record headers as span attributes. Outbound, that includes the `Authorization: Bearer <project>:<management key>` header on every Descope management call. Inbound, it includes callers' bearer tokens and the internal-endpoint secrets (`X-Identity-Key`, `X-Flow-Secret`, `X-Descope-Webhook-S256`). The backend's span hook overwrites only the `authorization` attribute ([conventions §9](conventions.md#9-no-secrets-in-logs)).

> `py-identity-model` (token validation, OIDC discovery and JWKS) reads no environment variables. `HTTP_TIMEOUT`, `JWKS_CACHE_TTL` and the other variables that releases before 5.0 read are ignored. The backend uses the library's defaults: a 30-second timeout on discovery and JWKS fetches, and discovery documents and key sets cached for one hour unless the provider's `Cache-Control: max-age` says otherwise.

> The three internal-endpoint secrets (`DESCOPE_WEBHOOK_SECRET`, `DESCOPE_FLOW_SYNC_SECRET`, `INTERNAL_IDENTITY_KEY`) do **not** block startup — the app logs a warning and the corresponding endpoint refuses traffic until the secret is set (`main.py:_warn_missing_secrets`).

## Frontend (Vite — inlined at build time)

| Variable | Default | Description |
|----------|---------|-------------|
| `VITE_OIDC_AUTHORITY` | — | Generic OIDC issuer/authority URL. When set, points the SPA login at any standard-OIDC provider and takes precedence over `VITE_DESCOPE_*`. |
| `VITE_OIDC_CLIENT_ID` | — | OIDC client ID for the SPA. Overrides `VITE_DESCOPE_PROJECT_ID`. |
| `VITE_OIDC_SCOPE` | `openid profile email` | Requested OAuth scopes (e.g. add `offline_access` for refresh tokens). |
| `VITE_OIDC_REDIRECT_URI` | current window origin | OIDC redirect URI. |
| `VITE_DESCOPE_PROJECT_ID` | — (**required** unless `VITE_OIDC_*` set) | Descope project ID for the SPA login (backward-compat fallback). |
| `VITE_DESCOPE_BASE_URL` | `https://api.descope.com` | Optional; set for a custom auth domain. |
| `VITE_API_BASE_URL` | `""` | Empty ⇒ relative `/api/...` (standalone, proxied by nginx). Gateway mode sets this to the Tyk URL so the browser hits the gateway directly. Because Vite inlines it at build time, each mode needs its own image. |

The `VITE_OIDC_*` variables are provider-neutral: when set they target the login flow at any standard-OIDC provider (e.g. Ory) and override the `VITE_DESCOPE_*` fallback per-field. Leave them unset to keep using Descope. See [`frontend/.env.example`](../frontend/.env.example) for a worked example. `docker compose up --build` passes a `VITE_OIDC_*` variable to the image build only when it is set in the shell or the root `.env`; one set there wins over `frontend/.env`, and one left unset there is read from `frontend/.env`. For the compose Zitadel, `make zitadel-frontend` builds the image with the values of the applied `infra/zitadel` root ([zitadel.md](zitadel.md#the-spa-against-this-instance)).

Every API call the SPA makes names its active tenant in the `X-Tenant-ID` header, whatever the provider. A provider whose authorization is canonical (Ory, Zitadel, Keycloak) reads it to choose among the caller's memberships, so switching tenant changes the header and asks the provider for nothing; for Descope the token's tenant decides.
